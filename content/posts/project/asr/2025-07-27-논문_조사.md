## 논문 조사

Whisper Streaming을 인용한 모든 논문의 Abstract를 읽어보았다.
그 결과 약 40개의 인용 중 한 논문만이 성능 향상 관련 접근법을 제시했다.

해당 논문은 [Adapting Whisper for Streaming Speech Recognition via Two-Pass Decoding](https://arxiv.org/abs/2506.12154)[(번역)](/20250728_adapting_whisper_for_streaming_speech_recognition_via_two-pass_decoding__translation)이다.
논문의 대략적인 요지는 다음과 같다.

+ 논문의 목표는 CPU에서 real-time ASR을 가능하게 하는 것
+ 어닝 콜 데이터셋에 초점을 둠
+ Whisper을 Streaming으로 CTC-attention decoder와 하이브리드 로스를 사용하여 파인튜닝 함
+ Whisper Medium (756M)을 기반으로 파인튜닝 하였으며, 유사한 성능을 보임.

정리하자면, 파인튜닝을 통해 약간의 정확도 손실로 실시간 ASR에 사용가능하게 만들었다. 이다.
따라서, 나의 기여와 차이점이 있다.

## 실험 오류 수정

하이퍼파라미터를 최적화한 후, 테스트 셋을 통해서 최적의 wer를 갖는 하이퍼파라미터 셋을 선택하는 과정을 수행하였다.
이러한 과정은 테스트 셋을 검증 셋으로 활용하는 것과 똑같은 것이며, 이는 데이터 누수를 발생시킨다.
따라서, 현재까지 수행했던 모든 테스트를 삭제하였고, 최적화를 처음부터 수행하였다.
검증 단계는 ESIC 데이터셋은 기존 검증셋을 train과 validation 으로 나누었고, LibriSpeechCorpus는 기존에 있던 validation 셋을 사용한다.
지금 까지 수행했던 것과 같이, 파라미터를 단계적으로 최적화할 것이며, 가장 최적의 하이퍼파라미터 셋이 선택되면, 해당 하이퍼파라미터를 딱 한 번 테스트셋으로 평가할 예정이다.

## 모델 분석

### latency 문제

지금까지 엄청난 실수를 하고 있었다. 지금까지 latency 문제가 발생한 이유는 prompt 길이 제한을 두지 않은 문제 때문이다.
이때문에 너무 긴 prompt가 들어가는 상황이 발생했고, latency가 느려졌던 것이다.
프롬프트 길이를 제한하는 코드로 변경하였고, latency가 줄어들 것으로 예상된다.

{{< admonition type=info >}}

짧게 테스트해본 결과. 줄어들었다. 11초 정도 걸리는 상황이 0.5초 미만으로 단축되었다.

{{</ admonition >}}

### select 문제

단어를 선택할 때, 그룹의 대표성을 구하는 그룹 단어의 임베딩 벡터의 평균을 구하여 이와 가장 높은 유사도를 활용하는 코드가 있다.
이는 가장 적절한 단어를 고르는 과정과는 맞지 않다고 판단하여 제거했다.
또한, 이전 단어만을 반영하던 과정을 누적 데이터 반영으로 변경했다.

현재 순서대로 과거 단어만을 반영하여 현재 단어를 고려하는 알고리즘을 적용하였는데, 이미 전체 단어가 주어져있으니, 모든 문장 조합을 생성하여 문장 내부 단어 임베딩 유사도가 가장 높은 문장을 선택할까 고려중이다.

### Prompt 미사용 모델과 prompt 사용 모델간의 wer차이

이전 잘못된 실험에서, prompt를 사용하지 않은 모델(M)은 일반적으로 prompt 쓰는 모델(PM)보다 조금 더 높은 wer이 나타나는 경향이 보였다.
그러나, 실험 환경을 다시 구성한 후 테스트 한 결과, 그렇지 않은 경우가 있음을 알 수 있었다.
